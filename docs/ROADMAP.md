# Squid 安全与管理功能路线图

状态：P0–P3 已实现（0.1.6）；P4 未开始  
更新时间：2026-11-07  
适用平台：macOS 12+、Windows 10/11（x64；ARM64 通过兼容层运行）

本文是新版菜单、页面职责、授权流程和交付阶段的唯一规划来源。代码实现与本文冲突时，
先改本文并说明原因，再改代码。

## 1. 已确定的决策

1. 发布方式与 Shift 保持一致：macOS 使用 ad-hoc 签名 DMG，不公证；Windows 使用未签名、
   按用户安装的 NSIS。首次安装由用户通过 Gatekeeper / SmartScreen 自行授权。
2. 不使用本地自签证书。自签证书会让 macOS 直接显示“应用已损坏”，且没有可用的放行入口。
3. 不新增 daemon、系统服务、内核扩展或常驻特权 helper。需要管理员权限的动作，
   每次由系统弹窗授权。
4. 保留现有 8 个页面，新增「安全」和「启动项」两个页面。侧栏总入口变为 10 个。
5. 「安全」页负责扫描、发现、告警和隔离；隔离不单独开页面。
6. 「启动项」页负责持久化入口；进程管理不单独开页面，放入「实时监控」页签。
7. 首版不做 Cleanup + Security 的合并“智能扫描”。两个扫描入口使用不同措辞，
   避免用户以为一次扫描已经检查了所有内容。
8. 首版不做安全评分，只展示可验证的系统状态、扫描覆盖范围和发现数量。
9. 历史页首版仍只承载清理/卸载账本；安全扫描与隔离记录先放在安全页的“最近活动”。
10. 清理白名单与安全排除项是两份独立配置。清理白名单不能静默抑制恶意软件发现。

## 2. 发布与授权基线

### 2.1 安装与更新

| 场景 | macOS | Windows |
| --- | --- | --- |
| 首次安装 | 下载 DMG，拖入“应用程序”；首次启动由用户在 Gatekeeper 中放行一次 | 运行未签名 NSIS；SmartScreen 中选择“更多信息 → 仍要运行” |
| 应用内更新 | 校验文件大小、SHA256 和可选 Ed25519 清单签名；挂载 DMG、替换 App、清理 quarantine，不再弹 Gatekeeper | 校验后静默运行同一个 NSIS；失败时回退为手动打开安装包 |
| 安装权限 | 普通用户权限 | 普通用户权限，安装到 `%LOCALAPPDATA%\Programs\Squid` |
| 代码签名 | `signingIdentity: "-"`，保持 ad-hoc；发布检查必须显示 `Signature=adhoc` | 无 Authenticode；发布说明必须写明 SmartScreen 步骤 |
| 信任说明 | macOS 首次放行是系统信任提示，不是病毒扫描结果 | Windows SmartScreen 是系统信任提示，不是 Squid 的检测结果 |

应用内更新和规则包更新都不以“操作系统信任发布者”为前提，但必须继续做内容完整性校验。
清单签名解决“更新内容是否来自 Squid 发布者”，不能替代 Gatekeeper / SmartScreen。

### 2.2 首次授权卡

扩展现有 `SetupPanel`，从单一 Full Disk Access 检查变为非阻塞的“安全准备”卡片。
每项都显示状态、影响和修复入口，关闭卡片不改变任何设置。

| 检查项 | macOS | Windows |
| --- | --- | --- |
| 系统防护 | XProtect 版本、定义日期、后台/启动扫描是否开启、Gatekeeper 状态 | Defender / 第三方杀毒软件状态、实时保护、定义版本 |
| 扫描访问 | Full Disk Access 可选；未授权时跳过受保护目录并标注覆盖受限 | 通常无需额外隐私权限；安全中心不可读时标注状态未知 |
| 通知 | 请求通知权限；拒绝时保留应用内告警 | 请求通知权限；拒绝时保留应用内告警 |
| 登录启动 | 可选；用于托盘定时扫描和告警 | 可选；用于托盘定时扫描和告警 |
| 规则更新 | 可选；只下载签名规则包，不上传扫描结果 | 同 macOS |

首次扫描前再显示一次扫描范围确认：

- 快速扫描会覆盖哪些目录。
- 哪些目录可能触发 macOS 文件夹授权。
- 被拒绝或不可读的目录会在结果中明确标注“未检查”。

更新后重新检查权限。ad-hoc 身份会随构建变化，Full Disk Access、通知等授权可能被系统重置。
安全页顶部用一条“权限需要处理”提示承载，不再次强制弹窗。

### 2.3 用户授权边界

- 扫描本身不需要管理员权限。
- 当前用户拥有的启动项可以直接停用/恢复。
- 系统级启动项需要一次系统授权；不安装常驻 helper。
- 结束进程只处理当前用户拥有的进程；系统进程和他人进程只显示原因。
- 隔离、恢复、停用启动项默认每次确认。
- 自动隔离默认关闭；开启后也只处理“已确认”级别，不处理“可疑”级别。
- Windows 服务首版只读。
- macOS 登录项首版只读，修改入口跳转系统设置。

### 2.4 无 Developer ID / Authenticode 时的能力边界

无代码签名不会阻止 Squid 做本地扫描和用户授权范围内的处置，但会限制系统对发布者的信任，
以及后台接管能力。实现时不能把“用户放行”描述成“系统已认证安全”。

| 能力 | 无签名 / ad-hoc 时 | 边界 |
| --- | --- | --- |
| 首次安装与启动 | 可做 | 仍需要用户手动通过 Gatekeeper / SmartScreen；不承诺免提示 |
| 应用内更新 | 可做内容完整性校验 | SHA256 + 可选 Ed25519 清单签名；不能替代系统发布者信任 |
| 扫描用户文件 | 可做 | 受当前用户权限和 macOS Full Disk Access 限制 |
| 隔离与恢复 | 可做 | 只处理 Squid 自己记录、且重新校验通过的发现项 |
| XProtect / Defender 状态 | 只读查看 | 不调用系统扫描、不复制规则、不接管系统实时防护 |
| 用户级启动项 | 可做启停 | 仅限当前用户的 LaunchAgents / HKCU Run 等 |
| 系统级启动项 | 有限支持 | 每次依赖系统授权；不安装常驻特权 helper |
| 进程管理 | 可做当前用户进程 | 系统进程、他人进程只显示原因，不强制结束 |
| 常驻实时拦截 | 不做 | 没有内核扩展或系统服务；只在应用/托盘运行时做定时或手动扫描 |
| 通知 | 可做 | 依赖系统通知权限；拒绝后保留应用内告警和托盘状态 |

因此首版的安全定位是“本地按需扫描 + 可逆隔离 + 启动项/进程可见性”，而不是
CleanMyMac 式的常驻实时防病毒产品，也不是 XProtect / Defender 的替代品。

## 3. 菜单结构

### 3.1 侧栏

```text
维护 Maintenance
  电脑概览 Computer overview
  日常清理 Daily cleanup
  应用卸载 Uninstall apps
  深度清理 Deep Clean

保护 Protection
  安全 Security
  启动项 Startup items

洞察 Insights
  存储空间 Storage
  实时监控 Real-time monitor

（侧栏底部）
  历史记录 History
  设置 Settings
```

说明：

- 「安全」和「启动项」是新入口，放在「保护」组，不塞进「洞察」。
- 「实时监控」保持原名称，但页面内部增加「性能」和「进程」两个页签。
- 「历史记录」和「设置」继续固定在侧栏底部。
- 不新增「隔离区」「进程」「病毒扫描」等第三个入口，避免菜单膨胀。

### 3.2 页面 ID 与快捷键

| 序号 | Page ID | 中文 | English | 快捷键 |
| --- | --- | --- | --- | --- |
| 1 | `overview` | 电脑概览 | Computer overview | `Cmd/Ctrl+1` |
| 2 | `cleanup` | 日常清理 | Daily cleanup | `Cmd/Ctrl+2` |
| 3 | `applications` | 应用卸载 | Uninstall apps | `Cmd/Ctrl+3` |
| 4 | `purge` | 深度清理 | Deep Clean | `Cmd/Ctrl+4` |
| 5 | `storage` | 存储空间 | Storage | `Cmd/Ctrl+5` |
| 6 | `system` | 实时监控 | Real-time monitor | `Cmd/Ctrl+6` |
| 7 | `security` | 安全 | Security | `Cmd/Ctrl+7` |
| 8 | `startup` | 启动项 | Startup items | `Cmd/Ctrl+8` |
| 9 | `history` | 历史记录 | History | `Cmd/Ctrl+9` |
| 10 | `settings` | 设置 | Settings | `Cmd/Ctrl+0` |

`Cmd/Ctrl+7/8` 从原来的历史/设置改为安全/启动项；历史/设置顺延到 `9/0`。
升级说明中要写清楚这一变化。

### 3.3 托盘菜单

```text
打开 Squid
保护状态：正常 / 发现 2 个问题        （只读状态行）
扫描恶意软件
管理启动项
---
日常清理
应用卸载
深度清理
---
退出 Squid
```

行为：

- 托盘菜单跟随界面语言。
- “保护状态”是禁用状态行；有已确认发现时显示数量，点击系统通知直接打开安全页。
- 正在扫描时，“扫描恶意软件”变为“正在扫描…”并禁用。
- 托盘图标/提示文字显示保护状态；有高危发现时优先于“有更新”提示。
- 点击托盘通知默认打开安全页的发现列表。

### 3.4 导航徽标

- 「安全」：存在未处理的已确认发现时显示数量徽标；只有可疑项时显示普通圆点。
- 「启动项」：首版不加数字徽标，避免把正常的系统启动项也变成噪声。
- 「日常清理」：保留现有圆点。
- 「设置」：保留现有更新圆点。

## 4. 页面职责

### 4.1 页面总表

| 页面 | 主要职责 | 主要动作 | 不承载 |
| --- | --- | --- | --- |
| 电脑概览 | 汇总电脑状态、清理结果和安全状态 | 开始清理扫描、开始安全扫描、跳转 | 复杂发现处置、启动项编辑 |
| 日常清理 | 按规则扫描并删除可重建缓存和垃圾 | 选择、删除、撤销入口 | 安全发现和隔离 |
| 应用卸载 | 读取应用、生成卸载计划 | 卸载 App 与残留 | 安全扫描、启动项管理 |
| 深度清理 | 查找项目构建产物和旧安装包 | 选择、删除 | 安全扫描 |
| 存储空间 | 磁盘占用树和大文件 | 浏览、定位、打开 | 安全处置 |
| 实时监控 | 性能监控 + 全量进程管理 | 结束进程、查看进程详情 | 启动项启停 |
| 安全 | 系统防护、恶意软件扫描、发现、隔离 | 扫描、隔离、恢复、排除 | 编辑启动项、结束进程 |
| 启动项 | 管理登录/启动时运行的持久化入口 | 停用、恢复、查看关联进程 | 全量进程列表 |
| 历史记录 | 清理/卸载账本与恢复 | 查看会话、撤销 | 安全事件审计 |
| 设置 | 全局偏好、权限、排除项、更新 | 修改设置、打开系统设置 | 扫描结果和处置 |

### 4.2 电脑概览

职责：给用户一个“现在该做什么”的入口，不在这里完成复杂处置。

页面区块：

1. 顶部问候与设备信息（保留）。
2. 安全状态条：
   - 系统防护：XProtect / Defender 是否正常。
   - Squid 扫描：从未扫描 / 上次扫描 / 发现数量。
   - 覆盖范围：完整 / 受限。
   - 有未处理发现时替换为红色提示卡，按钮“查看发现”。
3. 清理扫描卡（保留现有磁盘仪表和清理结果）。
4. 两个明确分开的扫描按钮：
   - “清理扫描” / “Cleanup scan”
   - “安全快速扫描” / “Quick security scan”
5. 快捷入口：安全、日常清理、应用卸载、存储空间。
6. 性能概览（保留 CPU、内存、存储）。

首版不把两个扫描合并。用户必须能分清“释放空间”和“检查威胁”。

### 4.3 安全

职责：承载系统防护状态、恶意软件扫描、发现列表、告警和隔离区。

页面区块：

1. 页头：
   - “安全”标题。
   - 扫描按钮和扫描类型菜单：快速扫描 / 全盘扫描 / 自定义路径。
   - 扫描中显示进度、当前文件、取消按钮。
2. 系统防护卡：
   - macOS：XProtect 版本、定义日期、启动/后台扫描、Gatekeeper。
   - Windows：当前杀毒产品、实时保护、定义版本、最近扫描。
   - 状态不可读时显示“无法确认”，不使用绿色。
3. 覆盖范围卡：
   - 已授权目录、未授权目录、被跳过数量。
   - Full Disk Access 缺失时提供“打开系统设置”。
   - 规则包版本、上次更新、离线使用提示。
4. 发现列表：
   - 过滤：全部 / 已确认 / 可疑 / 已隔离。
   - 行内容：级别、名称、路径、证据、发现时间、建议动作。
   - 操作：隔离、在 Finder/资源管理器中显示、忽略一次、加入排除项。
   - 只有“已确认”项可批量隔离；可疑项只能逐条处理。
5. 隔离区：
   - 列表：原始路径、大小、发现原因、隔离时间。
   - 操作：恢复、永久删除、查看详情。
   - 空状态说明隔离区只保存 Squid 隔离的对象。
6. 最近活动：
   - 最近 20 次扫描、隔离、恢复；首版不写入历史页。
7. 空状态与错误：
   - 未扫描：“尚未扫描这台电脑”。
   - 扫描干净：“在已检查范围内未发现威胁”。
   - 覆盖受限：必须同时显示未检查范围，不能只显示“安全”。
   - 扫描失败：保留上次结果，不清空发现。

页面动作：

- 开始扫描、取消扫描。
- 更新规则包。
- 隔离/恢复/永久删除。
- 忽略一次/加入排除项。
- 打开系统设置、打开规则日志、打开隔离目录。

页面不负责：

- 启停启动项：跳转启动项页。
- 结束进程：跳转实时监控 → 进程，并带上 PID/路径过滤。
- 卸载 App：跳转应用卸载；安全页只提供入口，不自动生成卸载计划。

### 4.4 启动项

职责：展示并管理登录/启动时自动运行的持久化入口，解释每个条目的来源和风险。

页面区块：

1. 页头摘要：
   - 用户级数量、系统级数量、已停用数量、需要管理员授权的数量。
   - 不显示“优化分数”。
2. 过滤与搜索：
   - 范围：全部 / 当前用户 / 系统。
   - 来源：LaunchAgent、LaunchDaemon、登录项、Run/RunOnce、启动文件夹、计划任务、服务。
   - 状态：已启用 / 已停用。
   - 风险：全部 / 需要注意 / 仅系统项。
   - 默认隐藏 Apple / Microsoft 系统项，可开启“显示系统项”。
3. 列表：
   - 名称、来源、范围、发布者/签名、目标路径、状态、风险标签。
   - 风险标签：目标不存在、路径在临时目录、未签名、命令包含脚本解释器、近期创建、隐藏任务。
   - 风险标签只表示“需要检查”，不等于恶意。
4. 详情抽屉：
   - 完整命令、参数、工作目录、父 App、签名状态、文件哈希、修改时间。
   - 关联进程：显示 PID、CPU、内存，跳转实时监控 → 进程。
   - 操作：停用/启用、在 Finder/资源管理器中显示、扫描该文件、打开系统设置。
5. 修改确认：
   - 展示将被移动/修改的具体 plist、注册表值或任务。
   - 说明影响和恢复方式。
   - 系统级项目要求一次系统授权。
   - 操作后刷新真实状态，不只更新前端缓存。

首版操作范围：

| 平台 | 可直接操作 | 首版只读 |
| --- | --- | --- |
| macOS | 用户 `~/Library/LaunchAgents` | 全局 LaunchAgents/Daemons、登录项、Apple 系统项 |
| Windows | HKCU Run/RunOnce、用户启动文件夹 | HKLM、系统计划任务、Windows 服务 |

后续阶段：

- macOS 全局 LaunchAgents/Daemons：一次性管理员授权，备份后停用/恢复。
- Windows HKLM Run、系统计划任务：一次性 UAC 授权。
- Windows 服务：保持只读，不提供启停。
- macOS 登录项：保持只读，跳转系统设置。

### 4.5 实时监控

职责：性能监控与进程管理。不新增第三个进程页面。

页面页签：

1. **性能 / Performance**
   - 保留现有 CPU、内存、网络、磁盘、电池、卷、高占用进程。
   - 高占用进程标题右侧增加“查看全部进程”。
2. **进程 / Processes**
   - 全量进程表格，按需加载，不跟随 1Hz 刷新。
   - 列：进程、PID、父进程、用户、路径、CPU、内存、启动时间、签名、关联启动项。
   - 搜索、排序、按应用聚合、只看当前用户、只看未签名、只看有启动项。
   - 行详情抽屉：命令行、可执行文件、哈希、签名、工作目录、启动项、父进程。
   - 操作：结束进程、停止并隔离（仅已确认恶意）、打开文件位置、复制路径、跳转启动项。

安全约束：

- 保留现有 PID/名称复核和关键进程保护。
- 结束进程仍然只处理当前用户拥有的进程。
- “停止并隔离”必须来自安全发现项或用户显式选中的已确认项，不能对任意进程直接开放。
- 不自动结束“可疑”进程。

### 4.6 设置

保留现有设置，并增加安全相关区段：

1. 语言与外观（不变）。
2. 系统权限：
   - Full Disk Access。
   - 通知权限。
   - 登录启动（用于托盘定时扫描）。
   - Windows 安全中心状态。
3. 安全：
   - 扫描计划：关闭 / 登录后 / 每天 / 每周。
   - 发现高危时通知。
   - 自动隔离已确认项（默认关闭）。
   - 规则包自动更新（默认开启，可关闭）。
   - 扫描范围和默认排除项。
   - 安全排除项列表，独立于清理白名单；新增排除项需要二次确认并显示风险提示。
4. 启动：
   - 现有“开机自启”重命名为“登录时启动 Squid”，与“启动项”页面区分。
5. 删除安全（不变）。
6. 受保护位置（清理白名单，不变；说明它不影响安全扫描）。
7. 文件与信息：
   - 配置、历史、规则包、隔离区路径。
   - 构建信任状态：ad-hoc / 未签名，附发布说明链接。
8. 软件更新：
   - 应用更新和规则包更新分开显示版本与信任状态。

### 4.7 历史记录

首版保持不变：只显示清理/卸载会话和撤销。

安全扫描、隔离、恢复和启动项修改先放在安全页的“最近活动”。
后续如果增加“保护事件”页签，再迁移，不在首版混入清理账本。

### 4.8 日常清理、应用卸载、深度清理、存储空间

这四个页面保持现有职责，首版不做安全功能混入：

- 日常清理：不显示恶意软件发现。
- 应用卸载：不自动把可疑 App 加入卸载计划。
- 深度清理：不自动扫描或删除安全发现。
- 存储空间：只负责体积分析和定位。

跨页面跳转只提供入口，不把不同引擎的状态混在同一张表里。

## 5. 关键流程

### 5.1 首次启动

1. 用户完成 Gatekeeper / SmartScreen 首次授权。
2. 打开 Squid，显示“安全准备”卡片。
3. 卡片列出系统防护、访问权限、通知、登录启动和规则更新。
4. 用户可逐项处理，也可直接关闭。
5. 进入概览页；没有安全扫描时显示“尚未扫描”，而不是“安全”。

### 5.2 发现 → 隔离

1. 安全页展示发现项和证据。
2. 用户点击“隔离”。
3. 后端重新校验发现 ID、路径、哈希、文件身份和权限。
4. 移入 Squid 隔离区，写隔离清单。
5. 刷新发现列表和托盘状态。
6. 失败时明确说明原因：文件已变化、权限不足、正在运行、需要管理员授权。

### 5.3 进程 → 启动项

1. 用户在进程页打开某个进程详情。
2. 若进程关联启动项，显示“由启动项启动”。
3. 点击后跳转启动项页并定位该条目。
4. 启动项页不自动停用，用户再次确认。

### 5.4 通知

1. 高置信度发现产生系统通知。
2. 点击通知打开安全页并定位发现。
3. 通知权限被拒绝时，应用内红色提示和托盘状态仍然有效。
4. Squid 未运行时没有实时通知；用户可通过“登录时启动”让托盘常驻。

### 5.5 更新后权限检查

1. 应用内更新完成并重启。
2. 重新读取 Full Disk Access、通知和登录启动状态。
3. 权限丢失时在安全页顶部显示“扫描覆盖受限”，提供修复入口。
4. 不阻塞启动，不自动重新弹系统权限对话框。

## 6. 功能契约

### 6.1 扫描模式

| 模式 | 范围 | 默认 |
| --- | --- | --- |
| 快速扫描 | 应用目录、用户/全局启动项、浏览器扩展、Downloads/Desktop 中的可执行候选 | 是 |
| 全盘扫描 | 用户主目录、Applications、启动项目录；显式发起 | 否 |
| 自定义扫描 | 用户选择的文件或目录 | 否 |

默认不挂载 DMG、不递归解压归档、不扫描网络卷和未授权目录。

### 6.2 检测层

1. 系统防护状态：XProtect / Defender，只读。
2. 精确 SHA-256 哈希黑名单。
3. YARA-X 规则，覆盖 Mach-O、PE、脚本、App Bundle、浏览器扩展和启动项 plist。
4. 启发式风险：签名、路径、启动方式、伪装名称、异常参数。

级别：

- 已确认：哈希或高置信规则命中。
- 可疑：只有启发式证据，不自动隔离。
- 提示：签名/路径/启动项风险，仅展示。

### 6.3 隔离不变量

- 扫描不删除文件。
- 隔离只接受后端缓存的发现项 ID，前端不能提交任意路径。
- 移动前重新读取并核对哈希、大小、文件身份和权限。
- 不跟随符号链接。
- 不隔离系统目录、XProtect、Squid 自身和隔离区自身。
- 隔离区文件不可执行、权限受限。
- 恢复需要确认；永久删除只从隔离区发起。
- 隔离清单与清理账本分开。

### 6.4 启动项不变量

- 修改前备份原 plist、注册表值或启动文件夹条目。
- 每次只改一个条目，不做“一键全部禁用”。
- 系统级修改必须经过一次系统授权。
- 操作后重新读取真实状态，不信任前端缓存。
- 目标消失、权限变化、条目被 App 重建时，报告实际状态而不是假装成功。

### 6.5 规则包

- 内置基础规则，离线可用。
- 外部规则包使用独立 Ed25519 公钥验签，并校验 SHA256/大小。
- 只下载规则，不上传文件名、哈希或扫描结果。
- 验签失败、损坏或回滚时继续使用最后可用版本。
- 更新 `docs/SECURITY.md` 的网络说明。

### 6.6 性能预算

- 不新增常驻扫描线程。
- 空闲 0% CPU；安全页未打开时额外内存目标低于 20 MB。
- 扫描最多 4 个 worker，低优先级，可取消。
- 快速扫描目标 60 秒级；全盘扫描必须显式发起。
- 安装包增加目标不超过 10 MB；规则包压缩后目标不超过 5 MB。
- 哈希缓存按路径、大小、mtime、文件 ID 失效。

## 12. 实现后修订（0.1.6）

下面几条是写完、并在真机上量过之后必须回写给本文的差异。按本文开头的规矩：先改本文，
再改代码。

### 12.1 6.6 性能预算的实测结果

在 macOS 15.7.1 / 16 GB / NVMe 的开发机上，对真实主目录测量：

| 指标 | 目标 | 实测 |
| --- | --- | --- |
| 快速扫描耗时 | 60 秒级 | 冷启动 26 秒；命中判定缓存 9 秒 |
| 快速扫描读取量 | — | 约 1,900 个文件 / 6.2 GB |
| 全盘扫描耗时 | 显式发起即可 | 162 秒 / 50,070 个文件 |
| 遍历遇到的条目 | — | 约 105 万条，其中 34 万是无扩展名文件 |
| 空闲额外线程 | 0 个常驻扫描线程 | 1 个阻塞在 channel 上的定时线程，可被设置变更唤醒 |

「不新增常驻扫描线程」按原意保留：只有那个定时线程，它不轮询、不占 CPU，且只在应用运行
时存在（2.4 已写明没有 daemon）。

判定缓存与候选去重最初写成 `Vec` + `same_path` 线性查找，快速扫描因此跑到十分钟且 CPU
满核——看着像磁盘慢，实际是每文件上万次路径比较的纯 CPU 开销。改成按
`paths::canonical_key` 建索引后达到上表数字，并有测试断言 `canonical_key` 与 `same_path`
判定一致：键和判定不一致，就等于把一份缓存结论用到了另一个文件身上。

### 12.2 判定门槛（6.2 的必要补充）

6.2 说了有哪几层检测，没说**什么文件值得打开**。这是本项目里对可用性影响最大的一个决策，
写清楚：

1. 名字（遍历时免费）；
2. `stat`：大小上下限 + 执行位；
3. 目录形状：`.app` 内部只取主可执行文件与 `Info.plist`，否则光是 `/Applications` 就要
   多读十 GB；
4. 只有浏览器下载目录才去读文件头。

一条实测逼出来的修正：**扩展名要压过执行位**。解压压缩包会把里面所有文件都标成可执行，
于是「有执行位就算程序」在一台干净的 Mac 上报出 951 条假发现（`.class`、`.svg`、`.zip`、
`.DS_Store`）。现在的规则是：有名可查的按名字判断，无名可查的才看执行位。用户自己指名的
目录不受这条限制——那里按内容判定，因为 `eicar.com` 的后缀和它的身份本来就互相矛盾。

`.js` / `.json` / `.html` / `.lnk` 故意**不在**可执行扩展名里：它们在快速范围里有 35,288
个、1.31 GB；而恶意脚本真正的载体 `.ps1` / `.bat` / `.cmd` / `.hta` 只有 69 个文件、体积
几乎为零。全盘扫描与自定义扫描仍然看得到前者。

### 12.3 6.2 级别定义的收紧

「可疑」原先等于「有任何一条启发式证据」。在一台干净的 Mac 上这是 975 条。现在要求**两条
信号互相印证**——单个「无签名」只是「提示」，「无签名 + 开机启动」才是「可疑」。实测同一台
机器降到 8 条可疑 / 296 条提示，而这 8 条确实都值得看。伪装成系统组件仍然单独就能定为可疑，
因为没有正经程序会那么命名自己。

已发布探测器（哈希 / YARA）不受这条影响：它按自己的等级说话，也不替启发式充当第二条证据。

### 12.4 6.5 规则包的验签策略

6.5 要求「独立 Ed25519 公钥验签」，但没说构建里没有公钥时怎么办。按字面实现会让规则包在
除正式发布以外的每一个构建里永远更新失败。现在的做法与应用更新一致：

- 构建内有公钥 → 必须验签通过，否则拒绝（这是密钥的全部意义）；
- 构建内没有公钥 → 接受，但把 `provenance` 记成 `unverified` 并落盘，安全页与设置都写明
  「仅校验哈希，未验签」。

清单与包体仍然照 6.5 校验大小与 SHA-256；YARA 编译不过的包照样不允许成为 `current`。

### 12.5 与本文的两处措辞差异

- 4.3 的「扫描按钮和扫描类型菜单」实现为三个并列按钮（快速 / 全盘 / 自定义），不是下拉
  菜单：全盘与自定义的代价不同，摊开比收进菜单更不容易误点。
- 4.4 的风险标签在列表中只显示图标与短语，完整解释在详情抽屉里。一行六个橙色标签读起来
  和没有标签一样。

### 12.6 7.1 的模块划分与落点清单

7.1 写的是 `signatures.rs` 一个文件，实际需要三份互不相干的状态，硬挤在一起会分不清哪份
磁盘缓存对应哪个结论，所以拆成：

- `rules.rs`：哈希黑名单与 YARA 规则的编译与加载；
- `intel.rs`：规则包格式、验签、版本回退（与本文一致）；
- `store.rs`：扫描结果、发现、忽略项与最近活动的落盘。7.1 没提这个文件，但 6.3
  「前端只提交 ID」和 4.3「最近活动」都要求后端保存一份带 ID 的历史，它必须有归宿。

另外两处与清单的差集：

- 7.2 的命令表列了 12 条，实现为 18 条，多出 `security_open`（4.3 的「在 Finder 中显示」）、
  `security_ignore`（4.3 的「忽略一次」）、`security_settings_save`、
  `security_rollback_rules`（6.5 的回滚）、`open_quarantine_folder` 和 `process_stop`
  （4.5 的结束进程，清单把它漏在 `process_detail` 之后）。清单里的 `security_cancel` 实现了。
- 7.1 说 `squid-guard` 不依赖 `squid-engine`：成立；它只依赖 `squid-core` 与
  `squid-platform`。

### 12.7 界面不新增规范，并删掉重复解释

两个新页面第一版写完，界面自己变成了第二套设计系统：108 个新 class、两套 chip、两套
标签页、两个搜索框、两种图标按钮，外加 25 条超过 88 字符的解释文案。这一节把结论写死，
以后再加页面照此执行：

**复用，不新造。** 新页面一律用既有原语：卡片壳 `.panel`（和 `.apps-list-panel` 同一组
声明）、`.status-chip`（补 `is-success/warning/danger/info` 四个色调，而不是再造一个
`.state-pill`）、`.search-field`、`.icon-button`、`.text-button`、`.metric-icon` + `tone-*`、
`.quick-copy`、`.settings-row`、`.settings-select`、`.empty-inline`、`.host-card`、
`.confirm-extra`。`.startup-source` 曾经同时挂在一个 `<select>` 和一个 `<span>` 上，
`<select>` 改用 `.settings-select`。

**同一件事只有一种写法。** 发现行、启动项行、隔离行共用 `.item-row/.item-main/.item-copy/
.item-actions`；抽屉正文共用 `.item-detail`；统计块共用 `.stat`。`security-toggle` 组件本身
就是 `.settings-row` 的复制品，已删除。

**文案一条一句话。** 页面副标题 60–120 字符，和旧页面一致。同一个事实只在离它最近的
控件上出现一次：发现数以前在 `SectionTitle` 副标题和筛选 chip 各写一遍，现在只有 chip
带数字，而且 chip 上的数字就是点下去会看到的条数。

**不新增的规范也要说清楚。** 隔离行、启动项行原来各自定义了边框/圆角/背景，现在都来自
`.item-row` 一处；改一处两个页面同时生效，这正是不开第二套规范的目的。

### 12.8 6.6 的体积预算超了，并且部分是我自己造成的

6.6 写「安装包增加目标不超过 10 MB」。0.1.6 实测：

| 安装包 | 0.1.5 | 0.1.6 | 增加 |
| --- | --- | --- | --- |
| macOS universal DMG | 10,702,261 | 21,831,698 | **+10.6 MiB** |
| Windows x64 NSIS | 3,354,754 | 7,816,721 | +4.3 MiB |

两点都要写清楚，不要含糊过去：

1. **Windows 在预算内**（+4.3 MiB），macOS 略微超出。超出部分主要是 yara-x 把 wasmtime
   与 cranelift 拖了进来——`wasmtime` 在 yara-x 1.23 里是**必需依赖**，不是可选 feature，
   即便只开 `macho`/`pe` 这些模块也一样链接。想靠关 feature 省下来省不掉。
2. **第一次构建时报 `stripping debug info with rust-objcopy failed`**：`src-tauri` 被根
   workspace `exclude`，自己又没写 `[profile.release]`，所以桌面端从来没被 strip 过。
   补上 `strip = "symbols"` 后 universal 二进制从 85,043,456 降到 63,457,920 字节
   （−20.6 MiB），DMG 从 23.6 MiB 降到 20.8 MiB。也就是说：如果没有这次发现，超预算会
   严重得多；而 `panic` 仍然保持 unwind，因为「命令线程 panic 只失败一次请求」变成
   「整个应用退出」不属于这个版本该有的行为变化。

预算本身不改成 11 MB：超了就是超了，写在这里比改数字更有用。下一版如果要还这笔账，
方向是二进制本身（例如等 yara-x 提供关掉 wasm 后端的选项），不是砍功能。
